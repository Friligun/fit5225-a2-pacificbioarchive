## Role and contribution

I was responsible for the API, authentication boundary and persistence layer of Pacific BioArchive. I implemented and validated the FastAPI contracts for media upload, completion, retrieval, search, tags, deletion, subscriptions and temporary query files. I integrated Cognito JWT verification so production requests are tied to the authenticated Cognito `sub`, and added owner checks before media URLs, tags, thumbnails and deletion operations are exposed. I also worked on the DynamoDB repository and its owner-scoped checksum claim, including transactional duplicate handling so concurrent uploads of the same file do not create duplicate metadata. The API verifies the S3 checksum before placing a processing message on SQS, and accepts only signed worker callbacks. My work is evidenced by the API tests, persistence tests, anonymous HTTP 401 result, duplicate-upload result, query-by-file cleanup evidence and DynamoDB before/after screenshots in the evidence bundle.

I paid particular attention to failure handling and idempotency. S3 objects are removed only with an owner check, while metadata is retained when a storage deletion fails so the operation can be retried without silently orphaning data. Temporary query objects use a separate prefix and cleanup path rather than entering the permanent media index. I also documented the callback nonce and HMAC signature requirements so a delayed or forged worker response cannot update another user's record. These decisions connect the implementation to the rubric's access-control, deduplication and reliability requirements.

## Teamwork reflection

The main collaboration challenge was keeping the API contract stable while the frontend, dispatcher and Alibaba worker were developed independently. I found that documenting request and callback fields early made handovers much easier. Feedback from the worker and infrastructure work also exposed practical issues that were not visible in local tests, including timeout behavior and missing cloud permissions. We resolved these by recording the failure, changing one boundary at a time and rerunning the regression suite. The team worked well when each member owned a clear area but reviewed the cross-cloud flow together. We should improve by agreeing on a shared evidence naming convention and reviewing the final deployment checklist earlier, because some screenshots and operational checks were collected late.

I found code review most useful when it included a concrete request example or a failing cloud response. That made discussions objective and helped us distinguish a contract bug from an account or network problem. I would carry this practice into a future project by requiring a short integration checklist for every cross-service endpoint before the first live deployment.
